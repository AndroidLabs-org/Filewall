Permission Disclosure – Filewall: Secure Storage Provider

Every Android permission the installed app declares is listed below, including the ones contributed by the libraries it is built on. Nothing here is used to transmit or share your data externally.

Permissions the app requests

  • POST_NOTIFICATIONS
    Notifies you when an app asks for access to a protected folder, and carries the approve and deny actions for that request.
  • USE_BIOMETRIC and USE_FINGERPRINT
    Restrict access to the Filewall interface itself. USE_FINGERPRINT is the pre-Android 9 name for the same capability and is contributed by androidx.biometric; the app uses whichever one the device supports. Credentials are held by Android's Keystore and never leave the device.
  • RECEIVE_BOOT_COMPLETED
    Lets the app learn that the device has restarted so it can drop every authorisation granted before the reboot. Access has to be re-approved after a restart rather than surviving it.
  • QUERY_ALL_PACKAGES
    Reads the name and icon of the app behind a request, so a rule can say Files rather than com.google.android.documentsui, and so the app picker in Add rule can list the apps installed on the device. Only the label and the icon are read; no package list is stored or sent anywhere.

Permissions defined for the app

  • <package>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
    Declared by androidx.core at signature protection level. It exists so that broadcast receivers the app registers at runtime can only be reached by the app itself. No other app can hold it.

Permission the app enforces

  • MANAGE_DOCUMENTS
    The storage provider is declared with android:permission="android.permission.MANAGE_DOCUMENTS", so only the Android system may bind to it and other apps must go through the Storage Access Framework. This is a restriction the app imposes on itself — it is not a permission the app holds or can be granted.

Storage Access Framework

Filewall reaches your files only through the folders you pick with the system file picker. Those grants are issued by Android to Filewall, are visible under the picker's own permissions, and are not a manifest permission.
